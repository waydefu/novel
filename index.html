把混亂的國外詢價信，自動整理成可確認的報價草稿。

一句話：RFQ Pilot 是給貿易商、零件廠、模具廠用的 AI 工具，幫業助讀 Email、拆 BOM（物料清單）、查料號、查成本、做報價草稿，最後仍由人確認。

01

市場痛點：為什麼需要它？

業助每天都在做重複整理，而且大量詢價最後不會成交。最浪費的是「低成交率的前置整理工」。

資料很亂

客戶可能寄 Email、PDF、Excel、照片，還會在信中補一句「只報第 3、5 項」。

查料很花時間

客戶料號不一定等於公司料號，業助要翻舊報價、料號表、ERP。

報錯很危險

價格錯一個 0 就可能虧錢，所以 AI 不能直接寄正式報價，必須保留人工確認。

02

產品如何解決？

把 RFQ 處理拆成幾個安全步驟：AI 讀懂內容，資料庫提供真實資料，規則引擎擋風險，人做最後確認。

收信Email / 附件進來
讀文件OCR / Excel Parser
抽欄位客戶、數量、交期
查料號Exact / Fuzzy / No Match
查 ERP成本、庫存、交期
套規則毛利、風險、核准
人確認報價草稿完成
比喻：LLM（大型語言模型）像讀信助理；ERP（企業內部系統）像倉庫帳本；Rule Engine（規則引擎）像公司的報價守門員。
03

完整產品功能

正式產品不只是「AI 讀文件」，而是一整套 RFQ 工作系統。

RFQ Inbox

集中管理詢價信、附件、客戶、狀態，不再散落在每個人的信箱。

文件解析

讀 Email、Excel BOM、PDF，把混亂文件轉成乾淨表格。

料號匹配

分成 Exact（精準）、Fuzzy（相似）、No Match（找不到），避免 AI 亂猜。

ERP 查詢

查成本、庫存、MOQ（最低訂購量）、Lead Time（交期）。

報價規則

檢查最低毛利、成本是否過期、售價是否低於成本。

人工覆核

AI 產生草稿，業助確認，高金額再送主管核准。

版本追蹤

判斷 Rev.A / Rev.B 哪一個是最新版，避免報舊資料。

稽核紀錄

記錄每個欄位從哪裡來、誰修改、誰核准。

ROI 儀表板

統計節省工時、處理量、自動匹配率，讓老闆看得懂價值。

04

每個功能可用哪些 2026 技術？

下面用白話解釋。不是要全部都用，而是讓工程師可以依客戶環境選方案。

收件與附件匯入

把客戶寄來的 Email、Excel、PDF 收進系統。

  1. Microsoft Graph API（微軟郵件 API）適合 Outlook / Microsoft 365 客戶，能讀信件、附件、寄草稿。
  2. Gmail API（Google 郵件 API）適合 Gmail / Google Workspace 客戶，能讀取信件與附件。
  3. IMAP / SMTP（傳統郵件協定）老系統常用，像萬用插頭，幾乎什麼信箱都能接。
  4. Webhook / Inbound Email（信件轉事件）客戶寄到指定信箱後，系統立刻收到通知。
  5. n8n / Make（低程式自動化工具）先快速接流程，適合 MVP 測試。

文件解析與 OCR

把 PDF、掃描件、表格讀成機器看得懂的資料。

  1. Azure AI Document Intelligence（微軟文件理解）擅長抽文字、表格、欄位；適合企業客戶。
  2. Google Document AI（Google 文件 AI）把非結構化文件轉成結構化資料，也能處理版面與表格。
  3. Amazon Textract（AWS 文件辨識）適合已經在 AWS 上的公司，用來抽表格與表單。
  4. Unstructured（文件預處理平台）把 PDF、Office 文件切成好處理的段落與表格。
  5. PaddleOCR / Tesseract（開源 OCR）成本低、可自架，但複雜表格要自己補很多規則。

AI 欄位抽取

讓 AI 讀懂客戶信件，整理出客戶、數量、交期、交易條件。

  1. OpenAI / Azure OpenAI（大型語言模型）適合做穩定的文字理解與 JSON 欄位抽取。
  2. Anthropic Claude（大型語言模型）適合長文件與文字推理，能讀較複雜信件。
  3. Google Gemini（大型語言模型）適合搭配 Google Cloud / Document AI 使用。
  4. Mistral / Llama 自架模型資料不能出公司時可考慮，但需要更多工程維護。
  5. JSON Schema / Function Calling（固定輸出格式）限制 AI 按指定表格輸出，減少亂回答。

料號匹配與搜尋

找出客戶寫的料號對應公司內部哪個產品。

  1. PostgreSQL + pgvector（資料庫加相似搜尋）小到中型 MVP 很適合，一套資料庫同時放資料與相似比對。
  2. Elasticsearch / OpenSearch（文字搜尋引擎）適合料號、規格、描述的快速搜尋。
  3. Qdrant（向量資料庫）適合做語意搜尋，例如『M6 stainless screw』找相似產品。
  4. Pinecone（託管向量資料庫）不用自己維運，適合快速做 production。
  5. Weaviate（向量資料庫）支援語意搜尋與混合搜尋，適合知識庫型場景。

ERP / 成本資料串接

把料號連到成本、庫存、MOQ、交期。

  1. REST API（系統 API）最乾淨，ERP 有 API 時優先用。
  2. ODBC / JDBC（資料庫連線）老 ERP 常見，可直接讀資料庫或報表庫。
  3. CSV / Excel / SFTP（檔案交換）沒有 API 時最務實，定時交換資料。
  4. RPA（機器人操作舊系統）ERP 太老沒接口時，讓機器人模擬人操作。
  5. Airbyte / ETL（資料搬運工具）把不同系統資料同步到中間資料庫。

報價規則與風險檢查

決定什麼可以報、什麼要警告、什麼必須擋下。

  1. JSONLogic（JSON 規則）用 JSON 寫規則，工程師容易維護。
  2. Drools（商業規則引擎）複雜規則多時可用，但學習成本較高。
  3. 自建 Rule Service（自建規則服務）彈性最高，適合先做 MVP。
  4. SQL Rules（用資料庫規則）簡單毛利、成本檢查可直接用 SQL。
  5. 表格化設定（像 Excel 的規則表）非工程人員也能調整毛利與核准門檻。

工作流程與核准

讓每筆 RFQ 知道現在卡在哪一步。

  1. Temporal（工作流引擎）適合正式產品，能重試、追蹤、恢復失敗流程。
  2. n8n（流程自動化）MVP 快速串流程很好用。
  3. Camunda（BPM 流程管理）大型企業流程複雜時適合。
  4. BullMQ / Celery（背景任務隊列）適合處理 OCR、AI 解析這類耗時工作。
  5. 狀態機 State Machine把流程寫成清楚狀態，避免 UI 自己亂跳。

人工覆核與權限

AI 先做草稿，人負責確認與核准。

  1. React / Next.js（自建前端）最彈性，適合正式 SaaS 產品。
  2. Retool / Appsmith（內部工具平台）MVP 很快，適合先做後台。
  3. Power Apps（微軟低程式工具）公司用 Microsoft 生態時方便。
  4. RBAC（角色權限控制）業助、主管、管理員看到不同功能。
  5. SSO（單一登入）用公司帳號登入，降低導入阻力。

稽核、監控與 AI 品質

記錄 AI 做了什麼、花多少錢、哪裡錯。

  1. Langfuse（AI 觀測與評估）看每次 AI 呼叫、成本、錯誤與評分。
  2. OpenLIT（OpenTelemetry AI 觀測）用開放標準追蹤模型、工具與流程。
  3. OpenTelemetry（通用監控標準）像系統黑盒子，出事能回放流程。
  4. Phoenix / Arize（AI 評估工具）用來檢查 RAG、模型輸出品質。
  5. Audit Log（稽核紀錄）正式報價必備，知道誰改了什麼、何時改。

ROI Dashboard

讓老闆知道系統到底省了多少錢。

  1. Metabase（開源 BI）快速做報表，工程成本低。
  2. Power BI（微軟商業智慧）企業常用，適合給主管看。
  3. Looker Studio（Google 報表）簡單免費，適合早期展示。
  4. Grafana（監控儀表板）適合把系統效能與流程數據放一起。
  5. 自建 Dashboard最貼合產品，但開發成本較高。
05

最小 MVP：第一版只做什麼？

先做最容易落地、最能證明省時間的部分。不要一開始挑戰所有難題。

第一版要做

  • Email + Excel BOM 匯入
  • 欄位抽取：客戶、料號、數量、交期、交易條件
  • 料號 Exact / Fuzzy / No Match
  • 查成本、庫存、MOQ、交期
  • 產生報價草稿
  • 人工覆核與主管核准
  • ROI Dashboard

第一版不要做

  • CAD 工程圖全面辨識
  • 手機照片高準確辨識
  • 全自動寄正式報價
  • 所有 ERP 都串接
  • 所有產業都支援
06

12 週專案時程

這是可執行的 MVP 節奏。重點不是一次做完，而是第 8 週就能跑真實 RFQ。

階段時間做什麼目標
需求確認第 1–2 週收集真實 RFQ、料號表、報價流程知道最常見格式
解析與抽欄位第 3–4 週Email / Excel → 結構化 RFQ能整理出乾淨表格
料號與 ERP第 5–6 週料號匹配、成本庫存查詢能查到報價所需資料
報價草稿第 7–8 週規則檢查、毛利、Quotation Draft能產出可確認草稿
覆核與儀表板第 9–10 週人工覆核、主管核准、ROI能交給業助試用
Pilot 修正第 11–12 週用真實 RFQ 測試、修正錯誤達到可付費試點
07

產品開發人力配置

MVP 不需要大團隊，但需要懂 AI pipeline、前端流程與產業規則的人。

AI / Backend 工程師 1 位

負責文件解析、LLM 抽欄位、料號匹配、ERP 串接、規則引擎。

Frontend 工程師 1 位

負責 RFQ Inbox、覆核畫面、報價草稿、Dashboard。

產品 / 產業顧問 0.5–1 位

負責確認業助流程、報價規則、測試案例、客戶訪談。

QA / 導入支援 0.5 位

第 9 週後加入，幫忙測試真實 RFQ、記錄錯誤與教育使用者。

可選：ERP 顧問

如果客戶 ERP 很老，可能需要熟該 ERP 的顧問協助接資料。

可選：DevOps

正式上線、多客戶、資安要求提高後再加入。
